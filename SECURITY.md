# Security Policy

## Supported Versions

Security updates for Barvellum Suit for Adobe CC target the latest stable release for Windows and macOS.

| Version | Security updates |
| --- | --- |
| 1.6.3 | Supported |
| 1.6.2 and earlier | End of support |

If you find a vulnerability in an earlier release, you can still report it. Mention the version you tested and whether the issue also affects the current release.

## Reporting a Vulnerability

Open the repository’s [Security Advisories](https://github.com/poco98/Barvellum-Suit-for-Adobe-CC/security/advisories) page and select **Report a vulnerability** to send a private report to the maintainer.

If the button is unavailable, open an issue titled **Private security contact requested** on the repository’s [Issues page](https://github.com/poco98/Barvellum-Suit-for-Adobe-CC/issues). Include only the request for a private contact method. Keep vulnerability details, credentials and personal data out of public issues, discussions and pull requests.

Include the following in the private report when available:

- The Barvellum version, operating system and Adobe application version.
- The affected feature, installer or component. If the issue concerns a release file, include its filename and SHA-256 checksum.
- A description of the issue, its potential impact and the conditions under which it occurs.
- A minimal example using test data, if one is available. Remove credentials and personal data from logs and attachments.

## What to Expect

- **Acknowledgement.** The maintainer aims to acknowledge private reports within 7 calendar days.
- **Updates.** The maintainer aims to provide a status update at least every 14 calendar days while the investigation is active. Resolution time depends on the scope and complexity of the issue.
- **Confirmed reports.** The maintainer will assess the affected versions, work on a fix or mitigation, and coordinate disclosure with the reporter. A GitHub security advisory may be published with the affected versions and remediation. Reporters can choose whether to be credited.
- **Closed reports.** If the report is a duplicate, falls outside the project’s scope or cannot be confirmed, the maintainer will explain the decision in the private report where possible. Additional evidence is welcome.

Please keep vulnerability details private while we coordinate a fix or agree on a disclosure date.
